## 1. 需求分析

### 1.1 用户画像与使用场景

- **用户**：计算神经科学研究者，主要方向是帕金森病（PD）电生理、DBS/aDBS 闭环刺激、睡眠与步态、EEG/MEG/LFP 信号分析、神经动力学建模，以及 AI 方法在神经科学中的应用。
- **当前工作流**：把论文（PDF / 标题 / DOI / 链接）丢给 ChatGPT，按固定的五段模板让它总结，再连续追问细节（如"spindle 检测标准""Percept 能否改算法""UCSF 数据是否用于睡眠分期"）；定期把整段聊天导出成 Markdown 存档。
- **痛点**：
  1. 总结散落在很长的聊天记录里，**没有分类**，回头找某篇论文要靠全文搜索；
  2. 论文之间的联系（同一问题的不同回答、同一数据集、同一团队、互相矛盾的结论）只存在于脑子里或偶尔手写的"跨论文主题索引"中；
  3. 读过的论文多了以后**难以快速回忆**"读过什么、结论是什么、我当时质疑了什么"；
  4. 没有基于已读内容的**新论文推荐**。

### 1.2 从历史记录中提取的事实

对 `论文总结记录.md` 逐轮分析后，得到以下对软件设计有直接影响的观察：

| 观察 | 对设计的影响 |
|---|---|
| 27 轮对话里实际只有 **19 篇不同的论文**；第 01 轮是模板约定，第 27 轮是归档请求，属于非论文内容 | 导入时要能识别并跳过"非论文轮次" |
| 第 04 轮（medRxiv 403 无法访问）与第 05 轮是**同一篇论文**（同一 DOI） | 需要按 DOI / 链接 / 标题去重合并 |
| 第 07、09、11、12、19 轮是对上一篇论文的**追问**，不是新论文 | 需要"论文 + 追问线程"的数据结构，追问挂到对应论文下 |
| 第 10→11→12 轮出现了**纠错**（用户说"不要猜，基于论文给我答案"） | 需要记录"可信度/核实状态"和纠错历史 |
| 多篇论文带有"核实标记""历史精度提示""审读警示" | 每篇论文要有 `verification` 字段：全文已读 / 仅摘要 / 无法访问 / 存在纠错 |
| 每篇总结都有固定五段：背景与问题、方法与数据、结果与结论、团队与前后文献、批判性思考 | 用结构化字段存储，而非一整段文本；便于对比和检索 |
| 总结里有大量可抽取的实体：数据集（UCSF RC+S、NatMEG、ADAPT-PD）、设备（Medtronic Percept、SenSight）、方法（CCA、specparam/FOOOF、DDPM、MAML、Wilson–Cowan、Jansen–Rit）、模态（STN-LFP、ECoG、EEG、MEG、PSG、FDG-PET、MRI）、团队（Neumann、Voytek、Simonyan…） | 知识图谱的节点类型应围绕这些实体设计 |
| 每篇论文都附有原文链接，部分附代码链接（GitHub） | 链接/代码作为一等字段，并可用来拉取元数据 |
| 归档末尾已有手写的**跨论文主题索引 A–F**（beta 层级、睡眠/spindle、步态/FOG、aDBS 工程、AI 可解释性与因果边界、评估习惯） | 这本质上就是用户想要的"自动主题综述"，软件应自动生成并持续更新这类页面 |
| 反复出现的方法学原则：`temporal precedence ≠ causality`、`association ≠ mediation`、`necessary node ≠ generator`、`decoding alignment ≠ encoding alignment`、`same beta frequency ≠ same mechanism` | 图谱里增加"洞见/原则"节点，把论文作为例证挂上去，这是用户最有价值的个人知识 |
| 用户的评估习惯（F 节）：不要猜、检查 ground truth、区分预测与状态检测、重视部署约束、区分机理与模型推断 | 可写进改进版总结 Prompt，也可作为每篇论文的"审稿清单"字段 |
| 模板第 4 项要求"团队的前置或后续分析" | 推荐功能应包含"关注作者/团队的新论文" |
| 内容是**中英混排**（中文叙述 + 英文术语/标题） | 嵌入模型必须是多语种的 |

### 1.3 需求清单

**用户明确提出的需求**

| R4 | 基于已读论文**自动推荐**新论文 | P1 |
| R5 | 可以引入配置要求不高的开源小模型辅助 | 约束 |

| 编号 | 需求 | 理由 | 优先级 |
|---|---|---|---|

| S8 | **改进版总结 Prompt** 管理，让 ChatGPT 输出自带机器可读的元数据块 | 提高后续导入的准确率 | P1 |
| S9 | **时间线**：按阅读时间回看 | 回忆"最近读了什么" | P2 |
| S10 | **回忆/复习模式**（闪卡 + 间隔重复） | 帮助长期记忆 | P2 |
| S11 | 导出 Markdown / Obsidian 库 / BibTeX / JSON 备份 | 不被软件锁定 | P2 |
| S12 | 可选导入 PDF；可选与 Zotero 同步 | 后续扩展 | P3 |
| S13 | 本地优先，数据不出本机（除非用户配置了云端 LLM） | 未发表的想法属于隐私 | 约束 |

### 1.4 非功能需求

- **一键启动**：Windows / macOS / Linux 双击脚本即可，自动安装依赖并打开浏览器。
- **低配置可用**：无 GPU、8 GB 内存、不填任何 API key 也能使用全部功能（内置本地小模型）；填写云端 API 可提升质量。
- **规模**：面向个人论文库，设计容量 1–5,000 篇；不需要分布式组件。
- **可解释**：自动分类、推荐、图谱关系都要给出依据（相似论文、证据原文片段、置信度）。
- **AI 内容可追溯**：所有 AI 抽取的字段都标记来源（AI 抽取 / 用户确认 / 元数据库），并保存证据片段。

### 2.7 调研结论

1. **没有现成项目覆盖"对话式总结 → 自动分类 → 知识图谱 → 推荐"这条完整链路。** 现有工具几乎都以 PDF 为中心；你的核心资产是 ChatGPT 生成的结构化总结、追问和个人批判，这正是它们的盲区。
2. **最值得借鉴的设计**：
   - 分类路由：PaperRouter（嵌入 + LLM 双模式、置信度阈值、层级规则、拒绝反馈）；
   - 推荐：zotero-arxiv-daily（时间衰减加权相似度）+ arxiv-sanity-lite（按标签训练的小分类器）+ LocalCitationNetwork / literature-mapper（引用网络中的"缺失论文"）；
   - 图谱：literature-mapper（论断节点和支持/矛盾/扩展关系）+ Intern-Atlas（方法关系）+ GraphRAG（社区摘要 → 主题综述）；
   - 回忆：reor（相关论文侧栏）+ LLM Wiki（自动维护的主题页 + 健康检查）。
3. **决策**：自研一个轻量本地应用（Python 后端 + 网页前端 + SQLite），借鉴上述设计，并通过导出（Markdown / Obsidian / BibTeX）与 Zotero、Obsidian 保持互通，而不是把功能硬塞进某个现有项目。

## 3. 产品功能设计

### 3.1 功能总览

```
┌──────────────────────────────── PaperMind ────────────────────────────────┐
│  导入中心   收件箱(待确认)   论文库   知识图谱   语义地图   主题综述   问答   推荐   设置 │
└──────────────────────────────────────────────────────────────────────────┘
        │             │           │          │          │         │       │      │
   聊天记录/MD/   低置信度分类   结构化卡片  多类型节点  论文二维   自动维护  带引用   每日/按需
   ChatGPT导出    人工确认       多维筛选    关系网络    散点图    的主题页  的问答   新论文
```

### 3.2 F1 导入中心（R2、S1、S7、S8）

- **支持的输入**
  1. 归档 Markdown（即当前 `论文总结记录.md` 的格式）——规则解析，无需 LLM；
  2. ChatGPT 官方数据导出（`conversations.json`）——按对话树还原消息顺序；
  3. 直接粘贴一段聊天文本或单篇总结；
  4. （后续）PDF、DOI/URL 列表、BibTeX、Zotero 同步。
- **处理流水线**（详见 6.1）：拆分论文 → 结构化抽取 → 元数据补全 → 去重合并 → 自动分类 → 更新图谱。
- **幂等**：对原始内容做哈希，重复导入同一份归档只会新增未见过的论文；用户手动修改过的字段不会被覆盖。
- **导入报告**：新增 N 篇、合并 M 篇、追问 K 条、待确认 J 条，可逐条撤销。

### 3.3 F2 论文库与论文卡片（R1、S2、S3、S4）

- **列表视图**：按主题 / 文献类型 / 数据模态 / 方法 / 疾病 / 年份 / 核实状态多维筛选；关键词 + 语义混合搜索。
- **论文卡片**包含：
  - 标题、作者/团队、期刊、年份、DOI、原文链接、代码链接；
  - **一句话核心结论**（如 `necessary node ≠ oscillator generator`）；
  - 五段结构化总结（背景与问题 / 方法与数据 / 结果与结论 / 团队与前后文献 / 批判性思考）；
  - 关键数字（样本量、准确率、效应量等）；
  - 追问线程（原问题 + 回答要点）；
  - **核实状态**徽章：✅ 全文已读 / 📄 仅摘要 / ⛔ 无法访问 / ⚠️ 有纠错 / ❓ 未核实；
  - 分类标签（显示来源：自动 / 手动，以及置信度）；
  - 侧栏"相关论文"（语义相近 + 图谱邻居）。
- 所有字段可编辑，编辑后标记为"用户确认"。

### 3.4 F3 自动分类（R1、R2）

- **多维分面分类**（一篇论文可同时属于多个类别）：

| 分面 | 示例取值 | 生成方式 |
|---|---|---|
| 研究主题（树状） | PD 电生理与 beta 动力学 › beta 生成机制建模 | LLM 初始建议 + 用户调整，之后自动路由 |
| 文献类型 | 原始研究 / 综述 / 数据资源 / 计算模型 / 方法与工具 / 临床试验 / 技术报告 | LLM 抽取，固定枚举 |
| 数据模态 | STN-LFP、ECoG、EEG、MEG、PSG、FDG-PET、MRI、仿真 | 实体抽取 + 归一化 |
| 方法 | CCA、specparam、DDPM、MAML、Wilson–Cowan、Jansen–Rit… | 实体抽取 + 归一化 |
| 疾病 / 物种 | PD、肌张力障碍、抽动症；人、大鼠、猴 | 实体抽取 |

- **初始分类体系**：基于现有 19 篇论文由 LLM 提出建议（初稿见[附录 A](#附录-a基于现有-19-篇论文的初始分类草案)），用户在界面上增删、重命名、拖动调整层级。
- **新论文自动路由**：嵌入相似度 + 近邻投票 + LLM 判断三路融合，按置信度分为"自动归类 / 进收件箱待确认 / 建议新建类别"（算法见 6.3）。
- **从修正中学习**：用户在收件箱里的每次确认/拒绝都会更新类别中心向量和 LLM 的少样本示例。
- **体系演化**：某类别超过阈值（默认 15 篇）时，用聚类建议拆分子类；长期无新论文的类别提示合并。

### 3.5 F4 知识图谱与回忆（R3、S5、S9、S10）

- **节点类型**：论文、主题、方法/概念、数据集、数据模态、设备、作者/团队、**洞见/原则**、追问。
- **边类型**：

| 边 | 例子 | 来源 |
|---|---|---|
| 论文 → 主题 | ECoG→STN 生成 → 闭环调控工程 | 分类结果 |
| 论文 → 方法 / 数据集 / 设备 / 模态 | Directional aDBS → Medtronic Percept | LLM 抽取 + 归一化 |
| 论文 → 作者/团队 | ECoG→STN 生成 → Wolf-Julian Neumann | 元数据 / 抽取 |
| 论文 ↔ 论文（语义） | 两篇 aperiodic STN 论文 | 嵌入近邻（Top-k） |
| 论文 ↔ 论文（类型化） | Wilson–Cowan 模型 ⟷ 皮层-苍白球级联：**互补**；Nicollin 跨物种模型 ⟷ Wilson–Cowan：**挑战**（STN–GPe 环路单独产生的频率可能偏高） | LLM 判断 + 证据片段 |
| 论文 → 洞见/原则 | Nicollin → `necessary node ≠ generator`；ECoG→STN → `feature-statistical preservation ≠ sample-by-sample reconstruction` | LLM 抽取 + 用户整理 |
| 论文 → 论文（引用） | 通过 OpenAlex 获取 | 元数据 API |

- **视图**：
  1. **全局图谱**：按主题社区着色的力导向图，可按节点/边类型过滤，点击节点展开邻居；
  2. **论文中心视图**：以一篇论文为中心的两跳邻居（"这篇和我读过的哪些有关？"）；
  3. **概念/原则视图**：只显示方法、洞见和原则，论文作为例证——最适合复习"方法学原则"；
  4. **语义地图**：所有论文嵌入降维（UMAP）后的二维散点图，邻近即主题相近，类似 Connected Papers 的体验；
  5. **时间线**：按阅读时间排列（ChatGPT 导出带时间戳；归档 Markdown 无日期时按顺序并允许手动填写）。
- **主题综述页**（借鉴 GraphRAG 社区摘要 + LLM Wiki）：每个主题自动生成一页综述，结构类似现有的"跨论文主题索引 A–F"：核心问题、论文之间的关系、共识与分歧、方法学注意点、开放问题；每句话都链接到来源论文；有新论文进入该主题时自动增量更新，并做"健康检查"（发现矛盾、过时陈述）。
- **回忆模式**（P2）：闪卡，正面是标题，背面是一句话结论和主要批判；按间隔重复算法（如 FSRS）安排复习。

### 3.6 F5 问我的论文库（S6）

- 例：*"我读过的论文里，哪些对 beta 作为 aDBS 生物标志物提出了质疑？"*
- 流程：混合检索（关键词 + 向量 + 图谱邻居）→ LLM 基于检索到的总结作答 → **每个论点标注来源论文**，没有依据就明确说"库中没有相关内容"（呼应"不要猜"）。

### 3.7 F6 论文推荐（R4）

- **候选来源**：
  - 新论文：arXiv（q-bio.NC、eess.SP 等）、bioRxiv / medRxiv（neuroscience、neurology）、PubMed 关键词订阅；
  - 引用网络：库中论文的参考文献与施引文献（OpenAlex）；
  - Semantic Scholar 推荐接口（以库中论文为正样本）；
  - **关注的作者/团队的新论文**（对应总结模板第 4 项）。
- **打分与解释**：见 6.5；每条推荐都附带"为什么推荐：与你读过的 X、Y 相似；被你库中 3 篇论文引用；Z 团队的后续工作"。
- **分组展示**：每日新论文 / 经典缺失论文（库里多篇都引用但你没读过）/ 团队动态 / 按主题推荐。
- **反馈**：👍 感兴趣 / 👎 不相关 / 已读，用于更新个人兴趣模型。
- **一键转为 ChatGPT 总结任务**：复制改进版 Prompt + 论文链接，读完后把聊天记录导回来，形成闭环。

### 3.8 F7 设置与工具

- LLM 提供商（OpenAI 兼容接口：OpenAI / DeepSeek / 通义千问 / 内置本地模型 / 外部 Ollama 等）、嵌入模型、推荐数据源、关注的作者与关键词；
- 分类体系编辑器；
- 总结 Prompt 模板管理（内置[附录 B](#附录-b改进版论文总结-prompt) 的改进版，一键复制）；
- 导出：Markdown / Obsidian 库（每篇论文一个 `.md`，带双链）/ BibTeX / JSON 全量备份；
- 数据目录位置、自动备份。

## 6. 核心流程与算法

### 6.1 导入流水线

```
原始文件 ──► ① 解析为消息序列 ──► ② 拆分为"论文会话" ──► ③ 结构化抽取
                                                              │
     ⑦ 图谱更新 ◄── ⑥ 自动分类 ◄── ⑤ 去重合并 ◄── ④ 元数据补全 ◄┘
                                                    │
                                          低置信度 ──► 收件箱
```

1. **解析**
   - 归档 Markdown：以 `## NN. 标题` 切分轮次，以 `**用户（原文）**` / `**助手回复…**` 区分角色，提取 `原文`/`参考链接`/`代码` 链接——纯规则，无需 LLM；
   - ChatGPT 导出：遍历 `conversations.json` 的 `mapping` 树，取 `current_node` 回溯得到主线消息，保留 `create_time` 作为阅读时间。
2. **拆分论文会话**：规则优先——用户消息包含论文标题、DOI、arXiv/期刊链接或 PDF 附件时开启新论文；否则视为对上一篇论文的追问。规则无法判断时（例如纯文本粘贴）交给 LLM 判断：`new_paper / followup / non_paper`。
3. **结构化抽取**：LLM 按 Pydantic schema 输出 JSON（字段见附录 B 的 YAML 块）。如果助手回复本身已带改进版 Prompt 生成的 YAML 元数据块，则直接解析，跳过 LLM。
4. **元数据补全**：按 DOI → arXiv ID → URL → 标题模糊搜索的顺序查询 OpenAlex（备选 Crossref / Semantic Scholar），补全作者、年份、期刊、摘要、引用数和参考文献列表。
5. **去重合并**：DOI 相同，或标准化标题相同，或标题嵌入相似度 > 0.95 视为同一篇；合并时保留所有总结和追问，标记冲突字段供用户裁决。
6. **自动分类**：见 6.3。
7. **图谱更新**：实体归一化（别名表 + 嵌入相似度，例如 `aDBS` = `adaptive DBS`，`FOOOF` = `specparam`），写入边，计算 Top-k 语义近邻，对候选论文对调用 LLM 判断关系类型（见 6.4）。

### 6.2 初始分类体系的生成

1. 对全部论文生成"分类用文本"：标题 + 一句话结论 + 背景与问题 + 方法关键词；
2. 论文少于约 50 篇时：把所有论文摘要交给 LLM，要求提出 6–10 个一级主题、每个下设 0–4 个子主题，并给每个类别写一句描述（类别描述用于后续路由）；
3. 论文较多时：先用 BERTopic（UMAP + HDBSCAN + c-TF-IDF）聚类，再让 LLM 给每个簇命名和写描述；
4. 用户在界面上确认/调整，得到正式分类体系。

### 6.3 新论文自动路由

对每个"研究主题"类别 c 计算综合得分：

```
score(c) = 0.4 · sim(论文向量, 类别中心向量)          # 中心向量 = 类别描述向量与已有论文向量的加权平均
         + 0.3 · kNN 投票(Top-5 相似论文中属于 c 的比例)
         + 0.3 · LLM 置信度(给出类别名称+描述，要求 LLM 输出 Top-3 及置信度)
```

- 规则（借鉴 PaperRouter）：父类得分高时不重复推荐其子类；被用户拒绝过的类别进入该论文的黑名单。
- 决策：
  - `score ≥ 0.75`：自动归入；
  - `0.5 ≤ score < 0.75`：进入收件箱，显示 Top-3 建议，用户一键确认；
  - 所有类别都 `< 0.5`：建议新建类别（LLM 给出名称和描述）。
- 学习：用户确认/修正后更新类别中心向量，并把该样例加入 LLM 少样本示例池（每类保留最具代表性的 3 例）。
- 不使用 LLM 时：去掉 LLM 项，按前两项重新加权，阈值相应调整。
- 文献类型、模态、方法等分面直接取抽取结果，经实体归一化后入库，不需要路由。

### 6.4 论文间关系的判定

- 候选对：嵌入相似度 Top-k，或共享数据集/方法/团队的论文对；
- 对每个候选对，LLM 读取两篇论文的一句话结论和关键结果，输出 `{关系类型, 一句话说明, 置信度}`，关系类型 ∈ {互补, 矛盾/挑战, 扩展, 同一问题的不同回答, 方法借鉴, 无明显关系}；
- 只保存置信度高于阈值的关系，并保存说明作为证据；
- 洞见/原则节点：从每篇论文的"批判性思考"中抽取"X ≠ Y"类原则，与已有原则做相似度匹配，相同则合并、挂上新例证。

### 6.5 推荐打分

```
score(候选论文 p) = 0.45 · Σᵢ wᵢ·sim(p, 库内论文 i) / Σᵢ wᵢ        # wᵢ 随阅读时间衰减（zotero-arxiv-daily 思路）
                  + 0.20 · 兴趣分类器得分(p)                       # 按主题训练的逻辑回归/SVM（arxiv-sanity-lite 思路），用 👍/👎 反馈持续更新
                  + 0.20 · 引用信号(p)                             # 被库内多少篇论文引用/与之文献耦合（LocalCitationNetwork 思路）
                  + 0.15 · 作者信号(p)                             # 是否为关注的作者/团队
                  − 已读/已拒绝惩罚
```

- 粗排用以上公式取 Top-50，再由 LLM 精排 Top-10，并生成中文推荐理由（引用库内相关论文）。
- 每日定时运行（默认早 8 点），也可手动触发；结果存入 `candidate` 表。

### 6.6 主题综述的生成与更新

- 首次：对一个主题下的所有论文（一句话结论 + 关键结果 + 批判 + 论文间关系）做"分组 → 归纳"，按固定结构生成：核心问题 / 论文图谱叙述 / 共识 / 分歧与争议 / 方法学注意点 / 开放问题；
- 增量：新论文加入时只把"旧综述 + 新论文"交给 LLM，要求最小改动，并以 diff 形式展示给用户确认；
- 健康检查（每月或手动）：检查综述中的陈述是否仍有来源支持、论文之间是否出现新的矛盾。

## 7. 模型选型与配置要求

### 7.1 各任务的模型需求

| 任务 | 需要的能力 | 推荐方案 | 无 LLM 时的降级方案 |
|---|---|---|---|
| 解析归档 Markdown | 无 | 规则 | — |
| 拆分论文会话 | 弱 | 规则为主，LLM 兜底 | 只用规则 |
| 结构化抽取（五段 + 实体） | **强**（长文本中文理解 + JSON 输出） | 内置小模型：规则先切出五段和链接，模型只做实体抽取等短任务，并用 JSON Schema 约束输出；可选云端 API 提升质量 | 按五段标题做规则切分，实体只用关键词词典匹配 |
| 嵌入（检索、分类、相似度、推荐） | 中英多语种 | **本地** Qwen3-Embedding-0.6B（约 1.2 GB）或 bge-m3（约 2.2 GB） | — （本地即可，无需 LLM） |
| 分类路由 | 中 | 嵌入 + LLM | 只用嵌入 + kNN |
| 论文关系判定、主题综述、问答、推荐理由 | 强 | 内置小模型（质量一般）；推荐配置云端 API 或 16 GB 档的 9B 模型 | 只保留语义相似边；综述和问答不可用 |

> 模型名称都是可配置项。任何 GGUF 模型都可通过修改配置替换。

### 7.2 三种运行模式与配置要求

| 模式 | LLM | 嵌入 | 最低配置 | 说明 |
|---|---|---|---|---|
| **默认：内置本地模式** | 内置小模型（llama-server + GGUF，2–5B 级别） | 本地 | 4 核 CPU、8 GB 内存、10 GB 磁盘，无需 GPU | **无需任何 API key**，开箱即用；数据不出本机 |
| 增强模式 | 设置中填写 OpenAI 兼容 API（DeepSeek / 通义千问 / OpenAI 等），抽取、关系判定、综述、问答等重任务切到云端 | 本地 | 同上 | 质量更高；每篇论文约数千到一万 token，个人用量成本很低 |
| 无 LLM 模式 | 无 | 本地 | 4 GB 内存 | 规则解析 + 嵌入分类 + 语义图谱 + 基于相似度的推荐 |

### 7.3 本地模型运行时方案

- 应用通过 OpenAI 兼容接口访问模型；"本地提供方"是应用自己启动和管理的 `llama-server` 子进程（生成一个实例、嵌入一个实例，端口自动分配，随应用退出）。
- `llama-server` 获取方式（按顺序尝试）：
  1. 用户电脑：首次启动时从 llama.cpp 官方 GitHub Release 下载对应平台的预编译包（Windows / macOS arm64 & x64 / Linux），校验后放入 `data/bin/`；
  2. 若下载失败或平台无预编译包：`git clone` llama.cpp 指定版本并用 CMake 源码编译（需本机有编译器）；
  3. 用户也可在设置中手动指定已有的 `llama-server` 路径或已运行的 OpenAI 兼容端点（如 Ollama、LM Studio）。
- 云端开发环境：GitHub Release 下载被网络策略拦截（403），但 `git clone` 可用、有 gcc/cmake，因此用方式 2 源码编译。
- **不使用 PyPI 上的 `llama-cpp-python`**：它只有源码包，在 Windows 上需要 MSVC 编译，破坏"一键启动"。
- 模型文件首次启动时从 Hugging Face 下载到 `data/models/`（支持 HF-Mirror / ModelScope 镜像和手动指定本地路径），不进 git 仓库。
- 生成时使用 JSON Schema / GBNF 语法约束，保证输出是合法 JSON。
- llama.cpp 版本需固定，并足够新以支持候选模型的架构（MiniCPM5、LFM2.5 等新架构需较新版本）。

| 模型 | 发布 | 参数 | 许可证 | 备注 |

## 8. 一键启动与部署

### 8.1 用户视角

1. 下载/克隆仓库；
2. Windows 双击 `start.bat`，macOS 双击 `start.command`，Linux 运行 `./start.sh`；
3. 首次启动自动完成：安装 uv → 下载 Python → 安装依赖 → 获取 `llama-server` → 下载默认生成模型与嵌入模型（显示进度，可选国内镜像 HF-Mirror / ModelScope）→ 初始化数据库；
4. 自动打开浏览器 `http://127.0.0.1:8765`，首次进入设置向导：选择模型档位（8 GB / 16 GB 内存）、可选填写云端 API（跳过则使用内置模型）→ 导入 `论文总结记录.md` → 确认初始分类体系。

### 8.2 启动脚本逻辑（伪代码）

```bash
# start.sh
command -v uv >/dev/null || curl -LsSf https://astral.sh/uv/install.sh | sh
uv sync --frozen                 # 按 uv.lock 安装依赖（含 Python 本身）
uv run papermind serve --open    # 启动 FastAPI，静态前端已预先构建并随仓库/Release 分发
```

- 前端构建产物（`static/`）在 Release 中预构建，**用户不需要安装 Node.js**；
- 默认只监听 `127.0.0.1`，不对局域网暴露；
- 数据目录默认 `./data/`，可在设置中更改；每次启动自动备份数据库（保留最近 7 份）。

### 8.3 后续可选打包

- PyInstaller 打包为单个可执行文件，或用 Tauri 包装为桌面应用；
- 提供 `docker-compose.yml`，方便部署到 NAS/服务器。

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| LLM 抽取出错或编造（与"不要猜"相悖） | 每个字段保存证据片段；AI 内容与用户确认内容在界面上明确区分；抽取 Prompt 要求"原文没有就留空"；关键数字附带原文引用 |
| 归档本身是"整理版"而非逐字记录，其中数字可能未经核实 | 继承归档中的核实标记，导入后默认 `verification = 未核实`，鼓励对照原文确认 |
| 实体归一化不准，图谱噪声大 | 内置神经科学常用别名词典（aDBS、FOOOF/specparam、STN/subthalamic…）；提供实体合并/拆分界面 |
| ChatGPT 导出格式变化 | 解析器做成插件式，并保留"粘贴文本"这一兜底入口 |
| 外部 API 限流或不可用（Semantic Scholar 等） | OpenAlex 作为主数据源；请求缓存；失败重试；推荐功能可离线降级为只用库内相似度 |
| 嵌入模型下载慢（国内网络） | 支持 HF-Mirror / ModelScope 镜像；允许手动指定本地模型路径 |
| 分类体系随时间变得混乱 | 拆分/合并建议；分类体系变更有历史记录、可回滚 |
| 隐私 | 默认本地运行、仅监听本机；只有用户配置的云端 LLM 会收到论文内容，设置页明确提示 |
