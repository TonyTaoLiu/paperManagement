# 模型评测（真实实测）

> 所有数字来自本仓库脚本在真实模型上的实际运行：`scripts/eval_models.py`（生成/嵌入）、`scripts/eval_router.py`（M2 路由）、`scripts/eval_table.py`（出表）。原始结果在 `data/eval/*.json`（未提交）。没有任何估算值。

## 1. 评测环境与方法

- 云端容器：4 核 vCPU（AVX2，无 AVX-512）、约 15 GB 内存、**无 GPU**；llama.cpp `b11721` 源码编译（可移植 CPU 分发构建），llama-server 单槽（`-np 1`）。**速度只代表这类弱 CPU**，常见笔记本会更快。
- 评测集：`论文总结记录.md` 的 19 篇论文；标注来自开发文档附录 A（`tests/fixtures/gold.json`，主分类取一级类别）。
- 生成模型全部 Q4_K_M 量化，用 JSON Schema 约束输出，`temperature=0.1`、关闭 thinking、不重试（一次不合法即计为失败）。
- 指标：
  - **JSON 合法率**：一次生成即通过 Pydantic 校验的比例；
  - **文献类型准确**：与附录 A 的文献类型（映射到 7 类枚举）完全一致；
  - **模态/方法召回**：附录 A 的模态/方法关键词是否出现在抽取结果中（标准化后子串匹配）；
  - **抽取可溯源率**：抽取出的模态/方法/数据集/设备名称有多大比例真的出现在原文里（越高越不"编造"）；
  - **分类 Top-1/Top-3**：给定 8 个一级类别的名称+描述，模型排名与附录 A 主分类一致的比例；
  - 速度、峰值内存（`VmHWM`）。
- 筛选：先用 5 篇（跨类别抽样）评测全部 7 个生成候选，再让前 3 名跑全部 19 篇。每测完一个模型即删除其文件。
- 局限：n 很小（19 篇，一篇 = 5.3 个百分点）；附录 A 的"文献类型""模态"标注有主观成分（例如"临床研究"映射到"原始研究"，部分模态只在追问里出现），因此"文献类型准确"普遍偏低，**更适合做模型间相对比较**而不是绝对值。

## 2. 观察与问题

- **MiniCPM5-1B / 2B**：JSON 合法，但分类 Top-1 仅 40–47%，文献类型几乎全错，质量不足以作默认；速度最快，适合极低配置的备选。
- **Qwen3.5-2B**：5 篇筛选中分类不稳定（Top-1 60%，Top-3 60%），不入围。
- **Gemma 4 E4B**：质量中等（5 篇 Top-1 40%），体积大（峰值内存近 8 GB）且最慢，不入围。
- **LFM2.5-8B-A1B**：在 llama.cpp `b11721` + JSON Schema 约束下对所有请求都返回空内容（5/5 失败），记入已知问题，未能评测其质量。
- **Qwen3.5-4B 与 9B**：19 篇上分类 Top-1 均为 95%、Top-3 100%，模态召回 87%、方法召回 72%；9B 文献类型准确略高（53% vs 47%），但"可溯源率"反而更低（54% vs 62%），速度慢约 1.7 倍、内存多约 1.6 倍。质量差距不大，因此 16 GB 档用 9B 主要是更长文本余量与略高的文献类型准确度。
- **内存**：llama-server 默认 4 个并行槽，每槽一份 KV 缓存，4B 峰值曾高达 9.6 GB；应用改为单槽（`-np 1`）并把 4B/9B 的上下文设为 6144 后，4B 重测峰值为 **5.4 GB**（3 篇重测）。9B 在单槽下的峰值未单独重测（上表 13.4 GB 是 4 槽时的数据，**不代表最终配置**）。
- 表中 19 篇的嵌入模型数据是在修复前缀配置之后重跑的（Qwen3-Embedding 使用 Instruct 查询前缀，EmbeddingGemma 使用 `task: search result | query:` 前缀）。早先一次未带前缀的运行已作废、不在表中。

## 3. 嵌入模型选择

三者在 20 条自然语言查询上 Top-3 都在 95–100%。**EmbeddingGemma-2**：查询 Top-1 90%、类别描述零样本 Top-3 100%（且 Top-1 最高 68%）、体积最小（0.31 GB）、最快（1.4 s/篇）、内存最低（约 0.5 GB）；Qwen3-Embedding-0.6B 查询 Top-1 略高（95%，差 1 条查询，属噪声范围）但更慢更占内存。**两档都默认 EmbeddingGemma-2**；Qwen3-Embedding、bge-m3 可在配置中替换。
纯向量的留一 1-NN（用其余 18 篇的标签投票）只有 26–42%：论文主题交叉很多，单靠近邻投票不足，所以路由需要类别描述向量与 LLM。

## 4. M2 路由验收（真实运行，应用自身的路由代码）

对 19 篇论文，用预置的 8 个一级类别（含描述）路由，子类别映射回一级类别后与附录 A 比较。"留一"模式：其余 18 篇带着标注作为已确认论文（稳态使用场景，参与 kNN 与中心向量）；"零样本"模式：只有类别描述。LLM 为 Qwen3.5-4B（8 GB 档默认）。

| 运行 | 配置 | 零样本 Top-1 / Top-3 | 留一 Top-1 / Top-3 |
|---|---|---|---|
| A（softmax τ=0.05） | 仅向量 | 63% / 95% | 53% / 79% |
| A | 向量 + LLM | 79% / 100% | 95% / 100% |
| B（τ=0.02，最终配置） | 仅向量 | 63% / 95% | 53% / 79% |
| B | 向量 + LLM | 100% / 100% | 79% / 100% |

- **验收标准**（Top-1 ≥ 80%、Top-3 ≥ 95%）：Top-3 在所有 LLM 运行中均为 100%，达标；Top-1 在 4 次 LLM 运行里有 2 次为 79%（差一篇），2 次分别为 95%、100%，**均值约 88%，但单次运行存在约 ±10 个百分点的波动**（LLM 输出随采样与提示中的少样本示例变化），因此只能说"基本达标、稳定性有限"，不是稳健达标。仅向量模式不达标（需要 LLM 或用户确认）。
- **决策阈值校准**：τ=0.05 时几乎所有论文都落入"建议新建类别"（15/19），τ 降到 0.02 后自动归类的论文全部正确（3/3、1/1），其余进入收件箱让用户一键确认；τ≤0.01 时自动归类开始出错（9/12 正确）。因此最终取 0.02，宁可多进收件箱也不自动归错。收件箱中每篇论文点击一次建议类别即完成确认（≤3 次点击）。

## 5. 最终选型

| 档位 | 生成模型 | 嵌入模型 | 理由 |
|---|---|---|---|
| 8 GB（默认） | **Qwen3.5-4B** Q4_K_M（2.7 GB，单槽峰值约 5.4 GB） | EmbeddingGemma-2 | 小模型中唯一达到可用分类质量（19 篇 Top-1 95%）；MiniCPM5-2B 虽小但分类 47%，不可用 |
| 16 GB | **Qwen3.5-9B** Q4_K_M（5.7 GB） | EmbeddingGemma-2 | 质量与 4B 接近，文献类型更准、上下文余量更大 |
| 极低配备选 | MiniCPM5-1B/2B 或"无 LLM 模式" | EmbeddingGemma-2 | 规则抽取 + 向量检索；分类靠用户确认 |

注意：8 GB 内存的机器需关闭其它大程序；CPU 推理较慢（本评测环境约 3 token/s），导入 19 篇并做 LLM 精修需要十几分钟，建议后台进行。
